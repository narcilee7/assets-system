# Python 运行时与 GIL 面试题集

---

## 一、CPython 解释器架构

### 题 1：Python 代码是怎么执行的？

**答案**：
1. **词法分析 / 语法分析**：源码 → AST。
2. **编译**：AST → 字节码（bytecode）。
3. **虚拟机执行**：CPython VM 逐条执行字节码。

```bash
python -m dis script.py  # 查看字节码
```

**考点**：
- Python 不是纯解释型，而是先编译为字节码再执行。
- `.pyc` 文件缓存字节码。

---

## 二、GIL（全局解释器锁）

### 题 2：什么是 GIL？它解决了什么问题？

**答案**：
- GIL 是 **Global Interpreter Lock**，保证同一时刻只有一个线程执行 Python 字节码。
- 它简化了 CPython 的内存管理（引用计数），避免多线程同时修改对象状态。

**代价**：
- 多线程无法并行执行 Python 字节码。
- 多线程对 CPU 密集型任务没有加速效果，甚至可能因为 GIL 切换而变慢。

---

### 题 3：多线程在什么场景下有用？

**答案**：
- **I/O 密集型**：网络请求、文件读写、数据库操作。
- 线程在等待 I/O 时会释放 GIL，其他线程可以执行。

**不适用**：
- CPU 密集型计算（应使用多进程或 C 扩展 / Cython）。

---

### 题 4：如何绕过 GIL？

| 方案 | 原理 |
|------|------|
| **多进程** | 每个进程有独立 GIL，真正实现并行 |
| **`multiprocessing`** | 基于进程，用 pickle 传数据 |
| **`concurrent.futures.ProcessPoolExecutor`** | 更现代的进程池接口 |
| **C 扩展 / Cython** | 在 C 层释放 GIL（`Py_BEGIN_ALLOW_THREADS`） |
| **`asyncio`** | 单线程事件循环 + 非阻塞 I/O |
| **`subinterpreters` (Python 3.12+)** | 每个子解释器独立 GIL |

## 三、内存管理

### 题 5：Python 怎么管理内存？

**答案**：
- **引用计数**：主要机制，对象被引用时 +1，引用消失时 -1，计数为 0 时立即释放。
- **循环引用检测**：`gc` 模块的分代垃圾回收处理循环引用。
- **内存池**：`pymalloc` 管理小于 512 字节的小对象，减少频繁向操作系统申请内存。

```python
import sys
a = []
print(sys.getrefcount(a))  # 引用计数 + 1（getrefcount 本身临时引用）
```

---

### 题 6：循环引用怎么解决？

```python
a = []
b = []
a.append(b)
b.append(a)
```

**答案**：
- 纯引用计数无法回收这种对象。
- `gc` 模块通过 **分代垃圾回收** 检测并打破循环引用。
- 可以通过 `gc.collect()` 手动触发，或设置 `gc.disable()` 关闭（不推荐）。

**考点**：
- `__del__` 与循环引用结合可能导致对象无法回收。
- 弱引用 `weakref` 可以避免循环引用。

---

### 题 7：分代 GC 的原理？

**答案**：
- 对象分为三代：0 代、1 代、2 代。
- 新对象在 0 代，存活过一轮回收后晋升到下一代。
- 老对象检查频率低，因为引用关系稳定。
- 回收时从根对象（全局变量、栈变量）出发，标记可达对象，不可达的对象回收。

## 四、asyncio 与事件循环

### 题 8：`async` / `await` 的原理？

**答案**：
- `async def` 定义协程函数，调用后返回协程对象（coroutine）。
- `await` 挂起当前协程，把控制权交还事件循环，等待可等待对象完成。
- 事件循环负责调度多个协程，在单线程内实现并发。

**考点**：
- 协程不是线程，不会并行执行。
- `await` 只能在 `async def` 内部使用。

---

### 题 9：`asyncio.create_task` 和 `await` 的区别？

**答案**：
- `await coro()`：同步等待，阻塞当前协程直到结果返回。
- `asyncio.create_task(coro())`：把协程包装成任务，立即调度执行，可并发运行多个任务。

```python
async def main():
    task1 = asyncio.create_task(fetch(url1))
    task2 = asyncio.create_task(fetch(url2))
    r1 = await task1
    r2 = await task2
```

---

### 题 10：`asyncio.gather` 和 `asyncio.wait` 的区别？

| 特性 | `gather` | `wait` |
|------|----------|--------|
| 返回 | 按输入顺序的结果列表 | `(done, pending)` 任务集合 |
| 异常 | 默认第一个异常会传播 | 不传播，需手动检查 |
| 用途 | 简单并发 | 需要更细粒度控制（如超时、取消） |

## 运行时与 GIL 速查卡

| 考点 | 一句话 | 陷阱 |
|------|--------|------|
| GIL | 单线程字节码执行锁 | 多线程不适合 CPU 密集 |
| 多线程 | 适合 I/O 密集 | 不能真正并行计算 |
| 多进程 | 绕过 GIL | 进程间通信成本高 |
| 引用计数 | 主要内存回收机制 | 循环引用需要 GC |
| 分代 GC | 三代回收，老对象低频 | `__del__` + 循环引用 |
| asyncio | 单线程事件循环 | 不要阻塞事件循环 |
| `create_task` | 立即调度并发 | 忘记 `await` 任务会丢失结果 |
