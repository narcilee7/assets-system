# Python 的诞生与演进目标

## 1. 诞生（Birth）：为什么会有 Python？

Python 诞生于 **1989 年圣诞节** 期间，由 **Guido van Rossum** 在荷兰数学和计算机科学研究学会（CWI）因“闲得无聊”而开始编写。它的诞生并不是凭空捏造，而是为了解决当时真实存在的工程痛点：

* **ABC 语言的遗产**：Guido 曾参与过 ABC 语言的开发。ABC 是一门极度优雅、易读、适合教学的语言，但它**不开放、不实用**（无法直接操作底层系统，甚至连读写文件都困难）。Python 继承了 ABC 优雅的语法（比如用缩进代替大括号），但走向了彻底的实用主义。
* **弥补 shell 与 C 之间的断层**：在 80 年代末，长脚本用 shell 编写会变成难以维护的灾难，而改用 C 语言编写又太慢、开发成本太高。Guido 需要一门**能够调用系统底层（操作系统 API、C 库），同时又具备高级脚本语言开发效率**的语言。

---

## 2. 核心设计目标（Goals）

Guido 在 1999 年向 DARPA 提交的 *“Computer Programming for Everybody”* 资助申请中，明确定义了 Python 的核心目标。直到今天，这些目标依然在深刻影响着 Python 的底层运行时设计：

* **简单直观，但威力强大**：它必须像主要竞争对手（当时是 Perl/Tcl）一样功能强大，但语法要极其干净。
* **完全开源**：以便任何人都能为之贡献，这也是为什么 Python 后来能在数据科学和 AI 时代形成恐怖生态的根源。
* **代码像纯英文一样易读**：降低代码维护成本。“阅读代码的次数远多于编写代码的次数”。
* **适合日常任务，开发周期短**：强调实用，拒绝学院派的过度设计（Over-engineering）。

---

## 3. 目标演进与历史性阵痛

理解 Python 现在的样子，离不开它在目标演进中经历的几次关键转变：

### Python 2 到 Python 3 的断代（2008）

* **核心目标：** **“清理历史包袱，回归语言的一致性”**。
* **代价：** 不向下兼容。最核心的修改是**彻底理清了 `str`（Unicode）与 `bytes` 的边界**，以及把 `print` 变成了函数。这次阵痛足足消耗了社区 10 年时间，但也让 Python 成功蜕变为一个现代化、能走向国际化（处理复杂字符集）的工程语言。

### GIL（全局解释器锁）的宿命

* **历史目标：** 在 90 年代初，多核 CPU 还没诞生，单线程性能是关键。为了让 CPython 能够极度简单地整合 C 扩展，同时保证线程安全，Guido 引入了 **GIL**。
* **现代目标（2025-2026 现状）：** 随着 AI 和多核时代的到来，GIL 成了最大的枷锁。Python 正在经历第二次历史性蜕变——PEP 703（选配移除 GIL）正在逐步落地。Python 的现代目标正在向“原生多线程并行”迈进。
