# Evolution

为了在 Part I — 01 章节中建立起最坚实的“历史直觉”，我们需要一份精准、硬核的 **Python 演进史与语言特性时间线**。

这份文档将帮你理清许多看似怪异的底层设计（例如：为什么 `async` 拖到 3.5 才有原生关键字？为什么 3.6 的 `dict` 突然变快了？）。我们将去除冗余的故事性叙述，直击**版本号、核心特性、底层运行机制（Runtime）变革**以及其背后的**设计动机**。

# Python 语言演进与特性时间线 (`evolution.md`)

## 1. 史前时代至黄金时代 (Python 1.x & 2.x)

这个阶段奠定了 Python 的基本骨架，并完成了向工业级语言的惊险蜕变。

### 1994 — Python 1.0 (初露锋芒)

* **核心特性：** 引入了函数式编程的基础算子：`lambda`、`map`、`filter`、`reduce`。
* **哲学动机：** Guido 早期其实并不热衷于函数式编程，但由社区贡献者实现后，因其强大的实用性被接纳，这为后来 Python 处理流式数据清洗埋下了种子。

### 2000 — Python 2.0 (社区与现代基石)

* **核心特性：** * **列表推导式 (List Comprehensions)**。
* **引入循环引用垃圾回收器 (Cycle-detecting GC)**。


* **底层变革：** CPython 在原有的引用计数（Reference Counting）基础上，正式引入了分代回收（Generational GC）算法，专门解决对象间死锁（循环引用）导致的内存泄漏问题。这是 Python 迈向长期运行服务的关键一步。

### 2006 — Python 2.5 (语法的现代化)

* **核心特性：** * **`with` 语句与上下文管理器协议 (`__enter__` / `__exit__`)** (PEP 343)。
* **生成器增强 (`yield` 表达式化)** (PEP 342)：`yield` 从单纯的产出值，变成了可以接收外部传入数据的双向通道（支持 `.send()`, `.throw()`）。


* **设计动机：** * `with` 解决了 C 语言扩展中频繁忘记释放文件描述符或锁的顽疾，让资源管理工业化。
* 生成器的增强，实际上为十年后出现的协程异步编程（Coroutine-based Async）暗中铺平了底层状态机的通路。

## 2. 大断代与凤凰涅槃 (Python 3.0 — 3.6)

这是 Python 历史上最痛苦的时期，经历了长达十年的新旧版本割裂，但彻底洗净了历史包袱。

### 2008 — Python 3.0 (清理乱象，不向下兼容)

* **核心特性：** * **彻底理清文本与二进制**：`str` 默认全为 Unicode（UTF-8），引入独立的 `bytes` 类型 (PEP 3101)。
* `print` 从关键字变成内置函数；所有的 `range`、`map`、`filter` 全面进化为惰性求值的迭代器（Iterator）而非直接返回列表。


* **底层动机：** 随着全球化互联网时代的到来，Python 2 模糊的 ASCII/Unicode 隐式转换引发了无数的 `UnicodeDecodeError` 灾难。Guido 宁可冒着社区分裂的风险，也要彻底重塑类型系统的底座。

### 2014 — Python 3.4 (异步的官方序曲)

* **核心特性：** 引入 `asyncio` 标准库 (PEP 3156)，此时使用 `@asyncio.coroutine` 装饰器和 `yield from` 语法来模拟异步控制流。

### 2015 — Python 3.5 (原生协程落地)

* **核心特性：** **正式引入 `async` 和 `await` 原生关键字** (PEP 492)。
* **底层变革：** 在 CPython 虚拟机内部，通过扩展 `PyTypeObject` 的槽位，将原生协程（Coroutine Object）与普通的生成器（Generator Object）在底层 C 类型上进行隔离。Python 正式具备了叫板 Node.js 事件循环的高并发底座。

### 2016 — Python 3.6 (性能与表达力的分水岭)

* **核心特性：** * **f-string (格式化字符串字面量)** (PEP 498)。
* **类型提示（Type Hints）变量注解语法** (PEP 526)。


* **底层变革：** **重构 `dict` 底层哈希表布局**。不再使用稀疏哈希数组，而是使用紧凑的一维数组存放 Key-Value，另用一个小型的索引数组指向它。
* *直接红利：* `dict` 的内存占用瞬间暴跌 **$20\% \sim 25\%$**，且由于遍历紧凑数组，字典意外获得了保持插入顺序（Insertion-ordered）的特性（并在 3.7 成为语言标准）。

## 3. 工业化与 AI 爆发时代 (Python 3.7 — 3.13+)

进入这个阶段，Python 成为 AI/ML 的绝对垄断语言，演进重心向**极致的工程化支持**与**运行时（Runtime）性能压榨**倾斜。

### 2018 — Python 3.7 (数据工程的解放)

* **核心特性：** 内置 `dataclasses` 模块 (PEP 557)。通过元编程显式自动生成 `__init__`、`__repr__` 和 `__eq__` 等样板代码，大幅简化了 DDD（领域驱动设计）中的贫血模型构建。

### 2019 — Python 3.8 (赋值与并发的基础设施)

* **核心特性：** * **海象运算符 `:=` (Named Expressions)** (PEP 572)。
* **`vectorcall` 调用协议** (PEP 590)：在 CPython 内部加速 C 扩展函数和类实例的调用效率，减少了临时元组（Tuple）和字典（Dict）对象的创建开销。



### 2021 — Python 3.10 (结构化模式匹配)

* **核心特性：** **引入 `match / case` 模式匹配** (PEP 634)。
* **设计动机：** 绝非简单的 `switch/case` 语法糖，而是可以直接对复杂的嵌套数据结构（如 JSON 响应、AST 语法树、Agent 决策状态）进行解构匹配，极大提升了复杂业务和 AI Agent 状态机的编写效率。

### 2022 — Python 3.11 (惊人的性能飞跃)

* **核心特性：** **“Faster CPython” 计划大放异彩** (PEP 659)。
* **底层变革：** 引入 **自适应特化解释器 (Specializing Adaptive Interpreter)**。虚拟机在运行时如果发现某段字节码（例如 `BINARY_OP` 加法）连续执行时都是同一种类型（如都是两个 `int`），就会在内部将该字节码动态替换为特化的快速字节码（如 `BINARY_OP_ADAPTIVE_INT`），直接跳过通用属性查找。
* *红利：* 官方运行时速度综合提升 **$10\% \sim 60\%$**，这也是近十年来纯虚拟机层面最大的单核性能突破。



### 2024 — Python 3.13 (打破枷锁的开端)

* **核心特性：** * **实验性支持移除 GIL (Free-threaded CPython)** (PEP 703)。
* **引入实验性 JIT（即时编译器）**。


* **现代动机：** 面对多核 CPU 时代的算力压榨需求，以及在大模型（LLM）推理、高并发 Agent Runtime 场景下对真多线程并行的极度饥渴，CPython 终于开启了对 GIL 的终极手术。

## 4. 核心演进脉络总结图

| 历史周期 | 演进主旋律 | 标志性底层突破 |
| --- | --- | --- |
| **Python 1.x / 2.x** | 奠定动态脚本基础，建立工业化生态 | 引入分代回收垃圾机制（解决内存管理痛点） |
| **Python 3.0 / 3.6** | 忍痛切断历史包袱，彻底拥抱现代化 | 原生 `async/await` 状态机；紧凑型 `dict` 内存剧降 |
| **Python 3.7 / 3.11** | 追求极致的工程健壮性与单核执行效率 | 类型提示体系全面成熟；自适应特化解释器（速度跃升） |
| **Python 3.13 +** | 迈向现代高性能多核 Runtime | 选配移除 GIL（Free-threaded）；引入原生 JIT 编译器 |
