# keyword

在 Python 3.13+ 的现代体系中，一共有 **35 个保留关键字**（随着语言演进，数量在不断微调）。
我们可以将所有关键字划分为以下 **6 大核心家族**：

---

## 1. 变量与命名空间控制家族 (6个)

这组关键字直接操控 CPython 的 `PyFrameObject`（栈帧）中的名字绑定与作用域链（LEGB 规则）。

* **`global`**：
* *底层真相：* 显式告诉编译器，当前作用域内对该变量的**赋值操作**应当直接映射到当前模块的 `f_globals`（全局字典）中，而不是在 `f_locals`（局部局部数组）中创建新引用。


* **`nonlocal`**：
* *底层真相：* 用于闭包。迫使编译器在闭包的自由变量（Cell Variables）层级中向上查找，修改外层嵌套函数而非全局作用域的变量。


* **`import` / `from` / `as**`：
* *底层真相：* `import` 底层触发的是内置函数 `__import__()`。它会先检查 `sys.modules` 缓存。如果不存在，则触发寻桩机制（Finders/Loaders），加载字节码并执行该模块文件，最后在当前作用域的 `f_locals` 中绑定对应的名字。`as` 则是纯粹的局部名字重定向。


* **`del`**：
* *底层真相：* 并不是删除内存中的对象，而是**解除名字绑定（减少一次引用计数）**。其对应的字节码是 `DELETE_FAST`（局部）或 `DELETE_GLOBAL`（全局），当对象的引用计数降为 0 时，由运行时触发内存回收。



---

## 2. 异步与惰性控制流家族 (5个)

Python 走向高性能并发与流式计算的语法核心。

* **`yield`**：
* *底层真相：* 只要函数体内包含 `yield`，编译器在编译期就会将其标记为 `CO_GENERATOR`（生成器）。调用该函数不会执行代码，而是返回一个封装了 C 语言执行栈帧的 `PyGenObject`。每一次 `yield` 都是用户态的“挂起”和状态保留。


* **`async` / `await**`：
* *底层真相：* `async def` 定义了一个原生协程（`CO_COROUTINE`）。`await` 关键字在底层等价于 `yield from`，它将当前协程的控制权交还给事件循环（Event Loop），直到被 `await` 的 `Awaitable` 对象（通常是 `Future` 或 `Task`）状态变为 Finished。


* **`return`**：
* *底层真相：* 终止当前栈帧的执行，向调用者传递对象引用。在生成器或协程中，`return value` 底层会抛出一个 `StopIteration(value)` 异常，用来传递最终结果。



---

## 3. 条件、循环与跳转控制家族 (10个)

控制虚拟机指令指针（Instruction Pointer）跳转的基础设施。

* **`if` / `elif` / `else**`：
* *底层真相：* 对应字节码 `POP_JUMP_IF_FALSE` 或 `POP_JUMP_IF_TRUE`。在底层进行布尔真值测试（调用对象的 `__bool__` 或 `__len__` 协议）。


* **`for` / `in**`：
* *底层真相：* `for...in` 是纯粹的**迭代器协议**语法糖。虚拟机首先调用 `iter(obj)`（触发 `__iter__`），然后不断执行字节码 `FOR_ITER`（内部调用 `__next__`），直到捕获 `StopIteration` 异常后优雅退出。


* **`while`**：
* *底层真相：* 循环条件跳转。只要条件评估为真，就反复跳转到循环体头部字节码处。


* **`break` / `continue**`：
* *底层真相：* `break` 直接让虚拟机修改指针，跳出当前的循环字节码块；`continue` 则直接跳转到下一次循环条件评估或 `FOR_ITER` 的起始位置。


* **`match` / `case**`（Python 3.10+ 引入）：
* *底层真相：* 软关键字（在特定上下文才具备关键字属性）。在底层由全新的字节码指令集（如 `MATCH_CLASS`、`MATCH_SEQUENCE`）支持，不仅做值相等性检查，还会动态解构对象的类型与属性。



---

## 4. 结构化异常与资源管理家族 (5个)

保证工程健壮性与 C 级资源安全的护栏。

* **`try` / `except` / `finally` / `else**`：
* *底层真相：* 虚拟机内部维护着一个异常处理表（Exception Table）。进入 `try` 块时，会在栈帧中注册一段字节码保护区。如果发生异常，虚拟机会查表匹配 `except` 后的类型。无论是否发生异常，`finally` 块中的字节码都**绝对会被执行**（甚至在 `try` 块里写了 `return`，也会先执行 `finally` 再返回）。


* **`with`**：
* *底层真相：* 上下文管理器协议的官方外壳。进入 `with` 时触发 `__enter__`，离开（包括异常崩溃）时**必然**调用 `__exit__`，常用于锁的自动释放和文件句柄的关闭。



---

## 5. 实体声明与元编程家族 (4个)

* **`def`**：
* *底层真相：* 编译期识别为函数。执行到该行时，虚拟机会在运行时实例化一个 `PyFunctionObject` 对象，将代码块（Bytecode）、全局命名空间、默认参数等组装在一起，并绑定到当前作用域。


* **`class`**：
* *底层真相：* 面向对象的起点。执行时，虚拟机会先执行类体内的代码（收集类属性字典），然后调用其元类（MetaClass，默认为 `type`）的 `__new__` 和 `__init__` 来动态铸造一个 `PyTypeObject` 结构体。


* **`lambda`**：
* *底层真相：* 匿名函数的快捷创建方式。在底层与 `def` 产生的对象完全一致，没有任何性能优势，仅仅是语法上的单行限制。


* **`pass`**：
* *底层真相：* 纯粹的占位符（NOP - No Operation）。在老版本中会生成 `NOP` 字节码，在现代 CPython 优化器中，`pass` 往往直接在编译期被剔除，不产生任何多余的字节码指令。



---

## 6. 表达式、字面量与逻辑运算家族 (5个)

* **`True` / `False` / `None**`：
* *底层真相：* 它们不仅是值，在标准库中是**绝对的单例对象（Singletons）**。所有对 `None` 的判断都必须使用 `is`（指针地址比较）而非 `==`（值比较），以压榨出极致的判空性能。


* **`and` / `or` / `not**`：
* *底层真相：* `and` 和 `or` 具备短路求值（Short-circuit evaluation）特性。`a and b` 如果 `a` 为假，根本不会对 `b` 进行求值，直接返回 `a`。


* **`is`**：
* *底层真相：* C 级别的指针比较。直接比较两个对象在 CPython 堆内存中的内存地址（即 `id(a) == id(b)`），速度极快。


* **`assert`**：
* *底层真相：* 断言。若条件为假则抛出 `AssertionError`。注意：如果运行 Python 时加上 `-O`（优化选项），所有的 `assert` 语句都会在编译期被**彻底抹去**，因此绝对不能用 `assert` 来做核心业务逻辑的参数校验。



---

### 💡 专家级认知：如何查阅当前的关键字？

无需死记硬背，在任何 Python 终端中，你可以通过标准库直接动态打印它们：

```python
import keyword
print(keyword.kwlist)  # 打印所有关键字
print(len(keyword.kwlist)) # 现代版本通常为 35 个

```
