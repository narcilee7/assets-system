# 复合类型底层原理 — 源码级速通

> 以下结构体定义来自 Go 1.22+ `runtime` 源码，面试能口述结构 + 机制即可。

---

## 1. Slice：Header + 数组视图

### 核心结构
```go
// runtime/slice.go
type slice struct {
    array unsafe.Pointer  // 指向底层数组
    len   int             // 可见长度
    cap   int             // 底层数组总容量
}
```

### 内存布局
```
栈上的 slice 变量 (24 bytes)
┌─────────────┬─────┬─────┐
│  array ptr  │ len │ cap │
│   8 bytes   │  4  │  4  │  (64位; 实际有padding到8)
└─────────────┴─────┴─────┘
       │
       ▼
堆上的底层数组
┌────┬────┬────┬────┬────┐
│ 0  │ 1  │ 2  │ 3  │ 4  │  ← cap=5
└────┴────┴────┴────┴────┘
```

### 扩容机制 `growslice`
```go
// runtime/slice.go
func growslice(et *_type, old slice, cap int) slice {
    // 1. 计算新容量
    newcap := old.cap
    doublecap := newcap + newcap
    if cap > doublecap {
        newcap = cap
    } else {
        if old.cap < 1024 {
            newcap = doublecap        // <1024: 2x
        } else {
            newcap += old.cap / 4     // >=1024: 1.25x
            // 直到对齐到内存页大小
        }
    }
    // 2. 内存分配 + 旧数据 memcpy
    // 3. 返回新 slice（array ptr 指向新数组）
}
```

**面试核心**：
- `append` 后如果 `cap` 够，**原地修改**底层数组，其他 slice 可见。
- 一旦触发扩容，`array` 指针变新地址，与原 slice **脱钩**。
- 零值 slice：`array=nil, len=0, cap=0`，不是 `nil` 指针（可安全 `range`）。

## 2. Map：hmap + bmap + 增量扩容

### 核心结构
```go
// runtime/map.go
type hmap struct {
    count     int              // 元素个数 (len)
    flags     uint8            // 写标记/迭代标记
    B         uint8            // 桶数 = 2^B
    noverflow uint16           // 溢出桶近似数
    hash0     uint32           // 哈希种子（防攻击）
    buckets   unsafe.Pointer   // 当前桶数组
    oldbuckets unsafe.Pointer  // 扩容时的旧桶（渐进迁移）
    nevacuate  uintptr         // 迁移进度
    extra     *mapextra        // 溢出桶缓存
}

type bmap struct {
    tophash [8]uint8           // 8个槽的哈希高8位
    // 之后紧跟着 8 个 key + 8 个 value（内存连续）
    // 再之后是 overflow 指针（下一个桶）
}
```

### 内存布局
```
hmap
┌──────────┐
│ buckets  │──► [bmap, bmap, bmap, ...]  长度 = 2^B
└──────────┘
                 │
                 ▼
              bmap (桶)
              ┌──────────┬──────────┬──────────┐
              │ tophash  │ keys     │ values   │──► overflow bmap
              │ [8]uint8 │ [8]key   │ [8]value │    (链表)
              └──────────┴──────────┴──────────┘
```

### 查找路径
1. 计算 `hash(key)`
2. 取低 `B` 位定位桶索引：`hash & (2^B - 1)`
3. 取高 8 位 `tophash`，在桶内线性探测
4. 如果桶满，沿 `overflow` 链表继续

### 扩容机制
```go

    // 每次写操作（insert/delete）时，迁移 1-2 个旧桶
}
```

**面试核心**：
- **并发读写直接 fatal error**：因为扩容时 `buckets` 指针会切换，旧桶被迁移，并发读写看到不一致的指针。
- `delete` 不释放内存，只是标记 `tophash` 为空槽。
- 遍历顺序随机：从随机桶、随机偏移开始。

## 3. Channel：hchan + 环形队列 + 等待队列

### 核心结构
```go
// runtime/chan.go
type hchan struct {
    qcount   uint           // 当前缓冲元素数
    dataqsiz uint           // 环形队列容量
    buf      unsafe.Pointer // 环形队列指针
    elemsize uint16         // 元素大小
    closed   uint32         // 关闭标志
    elemtype *_type         // 元素类型
    sendx    uint           // 发送索引
    recvx    uint           // 接收索引
    recvq    waitq          // 等待接收的 sudog 队列
    sendq    waitq          // 等待发送的 sudog 队列
    lock     mutex          // 全局锁（channel 不是无锁的！）
}

type waitq struct {
    first *sudog
    last  *sudog
}

type sudog struct {
    g          *g            // 绑定的 goroutine
    elem       unsafe.Pointer // 数据指针（直接拷贝，不经过 buf）
    next       *sudog
    prev       *sudog
}
```

### 内存布局
```
hchan
┌──────────┐
│   buf    │──► 环形队列 [v0, v1, v2, ...]
│          │    sendx/recvx 指针移动
└──────────┘
│  recvq   │──► sudog ──► sudog ──► nil
│  sendq   │──► sudog ──► sudog ──► nil
           (每个 sudog 挂一个阻塞的 G)
```

### 发送路径 `chansend`
```go
func chansend(c *hchan, ep unsafe.Pointer, block bool, callerpc uintptr) bool {
    lock(&c.lock)
    
    // 1. 有直接等待的接收者？
    if sg := c.recvq.dequeue(); sg != nil {
        // 直接拷贝给接收者的 sudog.elem（不经过 buf）
        sendDirect(c.elemtype, sg, ep)
        readyG(sg.g)  // 唤醒接收 G
        unlock(&c.lock)
        return true
    }
    
    // 2. 缓冲未满？
    if c.qcount < c.dataqsiz {
        // 写入 buf[sendx]，sendx++
        typedmemmove(c.elemtype, bufSlot, ep)
        c.qcount++
        unlock(&c.lock)
        return true
    }
    
    // 3. 阻塞：打包成 sudog，加入 sendq，挂起 G
    gp := getg()
    mysg := acquireSudog()
    mysg.elem = ep
    c.sendq.enqueue(mysg)
    gopark(chanparkcommit, ...)  // 挂起
}
```

**面试核心**：
- **无缓冲 channel**：发送方直接把数据拷贝到接收方的 `sudog.elem`，**不经过 buf**。
- **有缓冲 channel**：数据先进环形 buf，满了才阻塞。
- **关闭**：设置 `closed=1`，唤醒 `recvq` 和 `sendq` 中所有 G。`sendq` 中的 G 被唤醒后 panic（发现 closed）。
- **不是无锁的**：所有操作持有 `hchan.lock`。

## 4. Struct：内存对齐 + 嵌入字段

### 内存布局
```go
type Example struct {
    A bool     // offset 0, size 1
    // padding 7 bytes
    B int64    // offset 8, size 8
    C int32    // offset 16, size 4
    D bool     // offset 20, size 1
    // padding 3 bytes
}
// total size = 24, align = 8
```

**对齐规则**：
1. 字段偏移 = 字段大小的整数倍（或 1,2,4,8 中对齐值）。
2. 结构体总大小 = 最大对齐值的整数倍。
3. 空结构体 `struct{}` 大小为 0，但嵌入时如果作为最后一个字段，可能占 1 byte（防止不同对象指向同一地址）。

### 嵌入字段的底层
```go
type Inner struct { x int }
type Outer struct {
    Inner      // 嵌入
    y int
}

// 内存上等价于：
type Outer struct {
    x int      // Inner.x 被提升
    y int
}
```

**方法提升的底层**：
- 编译器在生成 `Outer` 的**方法表**时，会把 `Inner` 的方法**复制**到 `Outer` 的方法列表（不是继承，是扁平化）。
- 但 `Outer` 的**方法集**（值/指针）仍遵循规则：值接收者方法同时属于值和指针类型；指针接收者方法只属于指针类型。

## 5. Interface：eface / iface / itab

### 两种接口

**空接口 `interface{}`（eface）**：
```go
type eface struct {
    _type *_type          // 具体类型元数据
    data  unsafe.Pointer  // 数据指针（或内联小数据）
}
```

**非空接口（iface）**：
```go
type iface struct {
    tab  *itab           // 接口表
    data unsafe.Pointer  // 数据指针
}
```

### itab 结构
```go
type itab struct {
    inter *interfacetype   // 接口类型
    _type *_type            // 具体类型
    hash  uint32            // _type.hash 的拷贝（用于接口比较）
    _     [4]byte           // 对齐
    fun   [1]uintptr        // 变长数组：方法地址表
    // fun[0] = 接口第1个方法在具体类型中的地址
    // fun[1] = 接口第2个方法...
}
```

### 类型断言的底层
```go
// 断言 x.(T)
// 1. 拿到 x 的 _type（eface 直接取；iface 取 itab._type）
// 2. 比较 _type == T 的类型指针（或 hash）
// 3. 命中直接返回
// 4. 未命中：查全局 itabTable 哈希表，或生成新 itab
```

**itab 缓存**：
- 全局 `itabTable`（哈希表，大小约 512，可扩容）。
- 首次 `*Reader = MyReader{}` 时生成 itab，后续复用。
- 用 `atomic` 操作保证并发安全。

### 动态派发
```go
var r Reader = &MyReader{}
r.Read(buf)  // 汇编层面：

// 1. 从 iface.tab 取 fun[0]（Read 方法的地址）
// 2. 从 iface.data 取接收者指针
// 3. 直接 CALL fun[0]
```

**面试核心**：
- 接口调用是**两次间接访问**（读 tab → 读 fun[0]），比直接调用慢 ~2-3ns。
- 空接口 `interface{}` 少一层 itab，所以装值更快。
- `nil` 接口是 `(tab=nil, data=nil)`；装 nil 指针是 `(tab!=nil, data=nil)`，所以 `!= nil`。

## 6. 复合类型对比速查

| 类型 | 核心结构 | 分配位置 | 并发安全 | 零值行为 |
|------|---------|---------|---------|---------|
| **slice** | `{ptr, len, cap}` | 栈（header）+ 堆（数组）| ❌ | `nil`（可读不可写）|
| **map** | `hmap + bmap` | 堆 | ❌ fatal error | `nil`（可读不可写）|
| **chan** | `hchan + buf + sudog` | 堆 | ✅ 内部锁 | `nil`（读写阻塞）|
| **struct** | 字段顺序排列 | 栈/堆 | 依赖字段 | 各字段零值 |
| **interface** | `eface/iface` | 栈 | ❌（data竞争）| `nil`（装 nil 指针≠nil）|
