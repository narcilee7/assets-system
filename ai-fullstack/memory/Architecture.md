# Memory Architecture

**核心矛盾**：LLM 的上下文窗口有限（128K / 200K / 1M token），但 Agent 的任务可能持续数小时、数天，甚至跨会话。Memory 系统的任务就是在有限上下文里，塞进最有价值的信息。

## 架构设计

```plain
┌─────────────────────────────────────────────┐
│         Working Memory（工作记忆）            │
│    当前 LLM 上下文窗口里的内容                  │
│    长度：~128K tokens（模型限制）               │
│    生命周期：单轮/多轮对话                      │
├─────────────────────────────────────────────┤
│         Short-term Memory（短期记忆）          │
│    当前会话的历史，可快速检索                   │
│    长度：无上限（外部存储）                     │
│    生命周期：单次会话                          │
├─────────────────────────────────────────────┤
│         Long-term Memory（长期记忆）           │
│    跨会话的知识沉淀，用户画像，Skill            │
│    长度：无上限                                │
│    生命周期：永久                              │
└─────────────────────────────────────────────┘
```

### Working Memory

这是直接塞进 LLM Prompt 里的内容。它的设计原则是：只放当前决策必需的信息。

#### 组成

| 内容                | 来源                | 优先级                    |
| ----------------- | ----------------- | ---------------------- |
| System Prompt     | 静态模板              | 最高（必须保留）               |
| 工具定义（Tool Schema） | 静态/动态注册           | 高                      |
| Few-shot 示例       | 动态检索              | 中                      |
| 当前用户输入            | 用户                | 最高                     |
| 近期对话历史（原始/摘要）     | Short-term Memory | 高                      |
| 相关长期记忆（RAG 检索）    | Long-term Memory  | 中                      |
| 当前计划状态（Plan DAG）  | Planner           | 高（Plan-and-Execute 场景） |

#### 容量管理

问题：128K 上下文，System Prompt + Tool Schema 占了 30K，用户输入 2K，计划状态 5K，还剩 91K 给历史。但会话长了之后，历史会爆。

##### Solution

| 策略         | 原理                                         | 适用场景         |
| ---------- | ------------------------------------------ | ------------ |
| **滑动窗口**   | 只保留最近 N 轮对话                                | 简单聊天，历史不重要   |
| **摘要替换**   | 每 M 轮对前面内容做摘要，替换原始对话                       | 长会话，需要保留关键结论 |
| **关键事件保留** | 工具调用、错误、最终结论永久保留，中间推理可丢                    | Agent 场景     |
| **分层摘要**   | 第 1-10 轮 → 摘要1；第 11-20 轮 → 摘要2；摘要1 再被更高层摘要 | 极长会话，金字塔结构   |

### 短期记忆

这是当前会话的完整历史，存储在外部，需要时按需加载到 Working Memory。
