很好。**Array（数组）**看似简单，但它是几乎所有数据结构的基础。很多面试官会从数组开始，实际上是在考察你对**内存模型、CPU Cache、复杂度分析**的理解，而不仅仅是会不会做 LeetCode。

建议按下面的知识体系学习。

# 第一章 Array 的本质

一句话定义：

> **Array 是一块连续的内存空间，每个元素大小相同，因此可以通过下标进行 O(1) 随机访问。**

例如：

```text
int a[5]

地址：

1000
1004
1008
1012
1016
```

假设一个 `int` 占 4 Byte。

那么

```go
a[0]
```

地址就是

```
1000
```

而

```go
a[3]
```

CPU 根本不用遍历。

直接计算：

```
address = base + index * sizeof(T)

=1000+3×4

=1012
```

因此数组真正快的原因不是因为"下标"，而是**地址可以通过数学计算直接得到**。

# 第二章 为什么必须连续内存？

假设不是连续的。

```
1000

5000

9000

2000
```

那么

```
a[3]
```

CPU 根本不知道在哪。

只能：

```
1000

↓

5000

↓

9000

↓

2000
```

变成链表。

于是：

```
O(1)

↓

O(n)
```

所以：

> **连续内存，是随机访问成立的前提。**

# 第三章 Array 的时间复杂度

| 操作            | 时间复杂度 |
| ------------- | ----- |
| Random Access | O(1)  |
| Update        | O(1)  |
| Search        | O(n)  |
| Insert        | O(n)  |
| Delete        | O(n)  |

很多人容易误解：

```
Array 查询 O(1)
```

其实：

```
按下标访问

O(1)
```

而

```
查找某个值

O(n)
```

例如：

```go
nums := []int{8,4,9,2}
```

找：

```
9
```

需要：

```
8

↓

4

↓

9
```

# 第四章 为什么插入是 O(n)

例如：

```
1 2 3 4 5
```

在位置 2 插入：

```
9
```

必须移动：

```
4→5

3→4

2→3
```

变成

```
1 2 9 3 4 5
```

移动了：

```
n-index
```

个元素。

所以：

```
O(n)
```

删除同理。

# 第五章 Array 为什么 Cache Friendly（重点）

这是很多中高级面试都会问的。

CPU 读取内存不是：

```
读一个 int
```

而是：

```
读一个 Cache Line
```

现代 CPU：

```
Cache Line

通常 64 Byte
```

假设：

```
int =4 Byte
```

一次读取：

```
64/4=16 个整数
```

例如：

```
1 2 3 4 5 6 7 8 ...
```

CPU 实际一次全部读进 L1 Cache。

于是：

循环：

```go
for i:=0;i<n;i++{
    sum+=a[i]
}
```

访问的是：

```
L1 Cache

↓

L2

↓

L3

↓

Memory
```

大量命中 Cache。

---

如果是链表：

```
1000

↓

8000

↓

3000

↓

9000
```

CPU 每一步：

```
Cache Miss

↓

Memory

↓

Cache Miss

↓

Memory
```

速度可能慢几十倍。

因此：

> **数组最大的优势不仅是 O(1) 随机访问，更重要的是连续内存带来的 Cache Locality（缓存局部性）。**

这是数据库、操作系统、Go runtime 等底层实现中大量偏爱数组的原因。

# 第六章 Spatial Locality（空间局部性）

CPU 有一个假设：

> **如果你访问了地址 A，很可能马上会访问 A 后面的地址。**

例如：

```go
for i := 0; i < len(nums); i++ {
    sum += nums[i]
}
```

访问顺序：

```
0

↓

1

↓

2

↓

3
```

CPU 提前预取：

```
Prefetch
```

所以速度越来越快。

---

# 第七章 Temporal Locality（时间局部性）

如果一个数据刚访问过。

很可能：

```
马上再次访问
```

例如：

```go
for i := 0; i < n; i++ {
    x += nums[0]
}
```

`nums[0]` 会一直留在 Cache。

几乎不用访问内存。

---

# 第八章 Dynamic Array（动态数组）

面试真正喜欢问的是：

```
Array

↓

Dynamic Array
```

例如：

Go

```go
[]int
```

Java

```java
ArrayList
```

C++

```cpp
vector
```

Python

```python
list
```

它们底层都是：

```
连续数组
```

只不过：

```
容量不足

↓

申请更大的数组

↓

复制过去

↓

释放旧数组
```

例如：

```
capacity=4

1 2 3 4
```

Append：

```
5
```

变成：

```
capacity=8

1 2 3 4 5
```

这个扩容过程是 O(n)，但由于不是每次追加都会扩容，因此单次 `append` 的**均摊时间复杂度（Amortized Complexity）**仍然是 O(1)。

# 第九章 面试高频问题

几乎每家公司都会围绕下面几个问题展开：

1. 数组为什么能 O(1) 随机访问？
2. 为什么数组必须是连续内存？
3. 为什么数组插入和删除是 O(n)？
4. 为什么数组遍历通常比链表快，即使两者理论上都是 O(n)？
5. 什么是 CPU Cache、Cache Line、空间局部性和时间局部性？
6. 动态数组如何扩容？为什么 `append` 的均摊复杂度是 O(1)？
7. Go 的 `slice` 和数组有什么区别？（这是 Go 面试中的高频延伸，我们可以单独深入。）

**掌握标准**

学习数组时，不应停留在“数组是连续内存、查询 O(1)”这一层，而应能够从**内存布局 → 地址计算 → CPU Cache → 动态扩容 → 工程实现**这一完整链路解释它的性能特点。这种回答方式比单纯背诵复杂度更符合中高级工程岗位的面试预期。
